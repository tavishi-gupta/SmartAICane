Below is a full engineering-style design spec for your **Smart Autonomous Assistive Cane** project.

# Project Title

**SmartGuide Cane: Autonomous Agent–Based Assistive Cane for Blind and Low-Vision Users**

## 1. Project Vision

Build a smart cane using **Arduino-based sensors, camera-based object detection, Bluetooth phone connectivity, vibration alerts, and sound alerts** to help blind or low-vision users detect obstacles and navigate more safely.

The same system can later be adapted to:

* wheelchairs
* walkers
* delivery carts
* bicycles
* small robots
* warehouse moving objects

---

# 2. Core Problem

Traditional canes detect only obstacles that physically touch the cane. They may miss:

* objects at chest/head height
* moving obstacles
* glass doors
* low-contrast objects
* approaching people
* uneven surfaces
* obstacles slightly outside cane sweep range

This project adds a **sensor + AI layer** to detect obstacles before contact.

---

# 3. System Goals

## Primary Goals

1. Detect nearby obstacles.
2. Estimate obstacle distance.
3. Alert the user through vibration and phone sound.
4. Connect cane to mobile phone using Bluetooth.
5. Use camera-based object detection for higher-level awareness.
6. Keep system lightweight, low-cost, and modular.

## Secondary Goals

1. Log obstacle events.
2. Build a mobile dashboard.
3. Enable multiple alert modes.
4. Extend system to moving platforms.

---

## 5.2 Recommended Hardware Version

### Best beginner-friendly version

Use:

* **ESP32** instead of Arduino Uno

* **Ultrasonic sensor**

* **IR sensor**

* **Vibration motor**

* **Phone app**

### Best advanced version

Use:

* ESP32 or Raspberry Pi Zero 2 W
* Camera for object detection
* LiDAR / Time-of-Flight distance sensor
* BLE phone app
* TinyML model

# 6. Hardware Layers

## Layer 1: Sensing Layer

### Sensors

1. **Ultrasonic sensor**

   * Detects obstacle distance.
   * Range: ~2 cm to 400 cm.
   * Best for front-facing obstacle detection.

2. **IR sensor**

   * Detects nearby objects.
   * Useful for low obstacles.

3. **Camera**

   * Detects object type:

     * person
     * chair
     * wall
     * car
     * pole
     * stairs
     * door

4. **Optional IMU**

   * Tracks cane angle.
   * Helps avoid false readings when cane is pointed upward/downward.

---

## Layer 2: Edge Processing Layer

Microcontroller processes:

* distance values
* obstacle threshold
* object detection result
* alert priority

Example logic:

```text
If distance < 50 cm → High alert
If distance 50–100 cm → Medium alert
If distance 100–150 cm → Low alert
If camera detects person/car/stairs → Context alert
```

---

## Layer 3: Communication Layer

Bluetooth sends data to phone:

Example message:

```json
{
  "distance_cm": 42,
  "risk": "HIGH",
  "object": "chair",
  "direction": "front",
  "timestamp": "2026-04-26T10:30:00"
}
```

---

## Layer 4: Phone App Layer

Phone app receives Bluetooth data and triggers:

* sound alert
* vibration
* voice alert
* visual display for testing

Example voice alerts:

* “Obstacle ahead”
* “Object very close”
* “Person approaching”
* “Stairs detected”
* “Caution: moving object”

---

## Layer 5: Logging / Research Layer

Optional app stores:

* distance
* object type
* false positive / false negative
* GPS location
* time
* alert type

This creates data for future research paper or demo.

## 7.3 AI / Object Detection

### Option A: Beginner

Run object detection on phone camera.

Advantages:

* Easier
* More powerful phone processor
* Better camera quality

Flow:

```text
Phone camera → AI model → detect object → combine with cane sensor data
```

### Option B: Advanced

Run object detection on ESP32-CAM or Raspberry Pi.

Advantages:

* More independent cane
* Better engineering signal

Disadvantages:

* Harder
* Slower
* More power draw

### Recommended approach

Start with **sensor cane + phone object detection**.
Then later add **edge camera inference**.

# 8. Alert Logic

## Risk Levels

| Distance   | Risk   | Alert                               |
| ---------- | ------ | ----------------------------------- |
| >150 cm    | Low    | No alert                            |
| 100–150 cm | Low    | Light vibration                     |
| 50–100 cm  | Medium | Medium vibration + soft sound       |
| <50 cm     | High   | Strong vibration + loud voice alert |

---

## Alert Priority

| Object           | Priority   |
| ---------------- | ---------- |
| Stairs/drop-off  | Critical   |
| Moving vehicle   | Critical   |
| Person close     | High       |
| Chair/table/pole | Medium     |
| Wall/door        | Medium     |
| Unknown object   | Low/Medium |

---

## Haptic Pattern

| Risk     | Vibration Pattern    |
| -------- | -------------------- |
| Low      | 1 short pulse        |
| Medium   | 2 pulses             |
| High     | continuous pulse     |
| Critical | rapid repeated pulse |
